규명을 종합한다. V4_PLAN §9의 판정: **"V4 하이브리드가 recall에서 유의미하게 우위가 아니면
전량 확장을 중단하고, 부재판정·비교 기능만 유지하는 축소판으로 전환."**

## §9 판정: **전량 확장 중단 · 축소판 전환 + 추출 교정 선행**

V4 하이브리드는 recall에서 **일관된 우위가 없다**. 오히려 과소추출된 RW 진술계열에서는
keyword+정독 베이스라인보다 **열위**(RWI 0건, 진술 절반 누락)이고, 잘 추출된 특약·대금계열에서만
경쟁력이 있다. 따라서 §9 기준상 **현재 파이프라인으로 전량 확장을 계속해서는 안 된다.**

권고 경로(우선순위):

1. **전량 확장 즉시 중단.** 현재 확장은 추출 결함(IP·노무·보험 등 누락)을 전 코퍼스로 복제한다.
2. **추출 교정(②)을 확장보다 먼저.** RW 진술 하위영역 체크리스트 강제 재추출 +
   영역별 coverage 감사(`audit_rw_coverage.py`, complete 재정의). 재추출은 AI 클라이언트
   파일 하네스 배치(유료 API 없이). 교정 후 Gate B 재측정으로 우위를 재확인한다.
3. **축소판으로 운영 유지**: V4의 신뢰 가능한 부분만 노출.
   - 부재판정: 특약·선행조건·대금 family만(RW는 게이팅으로 needs_review — 구현 완료).
   - 비교(compare)·구조화 검색: 잘 추출된 family 위주.
   - 존재형 검색: 텍스트 FTS 폴백을 항상 병행(분류 누락 보완, 계획 원칙 5).
4. **분류 정밀도 교정**: 진술(rep)을 확약(covenant)으로 오분류하는 문제(E03) 시정 —
   rep는 RW.CONTRACTS/공시로, covenant만 COV로.
5. **T4(벡터)**: V4 추출이 안정될 때까지 계속 보류(재평가 대기).

## 요약
- 대표 기능(부재)은 **family별로 신뢰도가 갈리며 RW는 신뢰 불가** — 이미 게이팅으로 안전 처리됨.
- 확장의 전제(V4 recall 우위)가 성립하지 않음 → **확장 중단, 추출 교정 선행이 정답.**
- 추출을 고치면 V4의 잠재력(잘 된 family에서 실질 recall·부재판정 우위)은 실재하므로, 폐기가
  아니라 **교정 후 재평가**가 합리적이다.

  (추출 완전성이 상한이므로).
