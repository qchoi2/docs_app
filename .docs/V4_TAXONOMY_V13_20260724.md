# V4-6 taxonomy 정리 배치 — v13

작성일: 2026-07-24

## 해결 경로 보강

기존 taxonomy 후보 관리의 병합·승격은 후보 상태와 action log만 갱신하고,
후보 원문을 `v4_clause_item`으로 만들지 않았다. 이 상태에서 후보를 처리하면
관리 화면상으로는 해결되지만 원자 검색에서는 증거가 사라질 수 있었다.

schema revision 1R3와 관리 서비스를 다음과 같이 보강했다.

- 후보에 본문·별지 source, 원문 hash, taxonomy/extractor/prompt version을 저장
- merge/promote와 검색 item 생성을 하나의 `BEGIN IMMEDIATE` 트랜잭션으로 처리
- 후보 1개에 독립 명제가 여러 개이면 여러 taxonomy item으로 원자화 가능
- 원문 hash가 변경된 후보는 `STALE_CANDIDATE`로 중단
- 별지 후보는 대응하는 `v4_source_coverage`가 없으면 해결을 중단
- 생성 item의 qualifier·normalized 데이터에 후보 ID와 해결 근거를 기록
- 제목·리드인·편집주석을 reject할 때는 검색 item을 만들지 않음

운영 반영 전 pending 1,586개 전부가 현재 txt 캐시의 해당 ¶ 원문과 일치함을
확인했다(1,586/1,586, mismatch 0).
